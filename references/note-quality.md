# 精读笔记质量门

```bash
python scripts/lint_note.py --note "<库根>/paper-note.md"        # 单篇（生成后的交付闸门）
python scripts/lint_note.py --note <笔记.md> --force          # 强制检查非论文笔记
python scripts/lint_note.py --vault "<库根>" --selftest        # 全库体检（先自检再跑）
```

**生成笔记后必须跑一次，FAIL 清零再交付。** 与「配图体检」是两件事：
配图体检查**图有没有丢**（客观损坏），lint 检查格式、出处与链接等规范；方法解释是否充分仍须内容检查。

检查结果默认在终端输出，不在文献库或仓库根目录生成 `zotflow_lint` 等报告。确需保存时使用临时目录或项目 `.build/`，仅在用户要求时交付报告；不要复制检查脚本到仓库。

### 检查项

| # | 检查 | 级别 | 说明 |
|---|------|------|------|
| 1 | 每图必解读 | FAIL | 图后必须有人写的解读段；图后直接接标题即 FAIL |
| 2 | 公式必重现 | FAIL | 正文提到「式 N」就必须有 `\tag{N}` 的公式块 |
| 3 | 公式必直觉 | WARN | `$$` 块后应有解释段（行内 `$…$` 不查） |
| 4 | 论断锚点 | WARN | 有无 `[论文…]`/`[推断]`/`（§…, Table N）` 这类出处标注 |
| 5 | 禁人称词 | FAIL | 正文"你/我/咱"；`本人` 放行；附录整段豁免 |
| 6 | 章节完整性 | FAIL/WARN | 缺「方法与架构」「实验结果」= FAIL，其余缺 = WARN |
| 7 | 速览块 | WARN | 有无 `> [!abstract] 速览` |
| 8 | Zotero Key | FAIL | 存在且为 8 位 `[A-Z0-9]` |
| 9 | 图引用可解析 | FAIL | 死链 |
| 10 | MOC 收录 | WARN | 用 `--moc` 指定已有索引时检查收录；不为消除 WARN 新建 MOC |
| 11 | 链接目标有效 | FAIL/WARN | `[[…]]` 目标必须存在为文件 |

### 判读要点

1. **只有 FAIL 需要改**，WARN 是"看一眼"。退出码 1 当且仅当有 FAIL。
2. **1~8 项只对论文笔记生效**（优先判据：zotflow_type；旧笔记按 Zotero Key 兼容识别）。`计划.md`、`实验记录.md` 这类非论文笔记允许用"你/我"，
   不套用精读风格。9~11 项对所有笔记都跑——那是客观缺陷。
3. 使用 `--vault <目录> --moc <索引.md>` 显式指定已有 MOC 时检查收录；当前库没有使用 MOC 时不为消除 WARN 新建。笔记自身是否增加出链按研究需要，不以链接数量评价学习质量。
4. **拿存量笔记跑会有一批 FAIL，那是旧习惯不是脚本坏了**。不要为满足新模板自动回改历史笔记，
   结果只作为可选的整理线索；1~8 项真正的用途是给**新笔记**当闸门。
5. `--selftest` 在临时目录中验证已知缺陷与误报诱饵。修改检测器后应先运行自测；
   自测通过也不证明笔记的科学内容正确。
6. 误报是本工具最大的失败模式：把好笔记判死的检查器会被忽略，然后整个机制
   就废了。所以凡拿不准的都降级成 WARN，每条检查在代码里都注明了"故意不报什么"。

## 按产物限定检查

新科研产物保存成 Markdown 时，用 frontmatter 标记 `zotflow_type: resource-search`、`research-review`、`paper-comparison` 或 `experiment-review`。它们即使包含 Zotero Key，也只进入通用链接检查；不要求精读章节、速览、禁人称或每个式号重现。精读可标 `zotflow_type: close-reading`，旧精读不要求补字段。

组合科研报告以主要产物的单个模式作为 `zotflow_type`，其余模式可列在 `zotflow_workflows` 中。`zotflow_type` 不使用列表；不要因组合请求重新触发精读格式检查。

lint 只证明其列出的格式与链接检查；资源真假、研究建议是否现实、比较是否公平、实验结论是否过强，仍按相应模块检查。报告只留终端或项目 `.build/`，不在库根添加 lint 报告或检测器脚本。
