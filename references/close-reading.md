# 精读笔记与方法解释

### 输出定位：重点导向的学习笔记

默认目标是帮助用户快速掌握论文的核心问题、创新思路及对 WFM 学习的价值。完整读取和核对原文，输出时有选择地解释；用户明确要求全文翻译、复现细节或完整数据整理时，再按相应深度展开。

- **先判断主次**：重点是核心机制、为什么这样设计、相对已有方法的改变，以及批注与提问暴露的理解卡点；其次是验证创新的关键对照和消融；常规背景、训练配置、次要实验与全量数字不逐项搬运。
- **篇幅服从理解需要**：不设固定字数目标、硬性上限或压缩比例。优先压缩重复叙述、常规配置和数值复述；保留必要背景、推理步骤与关键证据，不以术语列表或一句结论替代解释。
- **保留核心解释链条**：关键设计按“问题 → 设计原因 → 如何实现 → 消融证据”讲透，明确监督对象、信息流、必要公式和组件分工。用原文对照或消融说明该设计的贡献；没有相关消融时明确证据缺口，区分作者解释与推断。批注和反复提问暴露的卡点允许多写，必要时补前置知识与小例子。
- **按学习价值分配篇幅**：方法、创新理由与 WFM 启发占主要篇幅。背景、动机和问题定义可合并；重复的结果与讨论也可合并。模版要求覆盖必要内容，不要求每个原文章节都有对应长段；保留足以支持理解和借鉴的实验设计依据与迁移条件。
- **实验围绕问题写**：优先讲“为什么这样安排对照/变量 → 结果支持或否定什么”。常规学习率、batch、epoch 不默认罗列；影响设计理由、公平性、指标解释或实际部署成本的条件必须保留。核心消融须交代改变了什么、控制了什么、观察到什么，不能只写“有效”或“互补”。
- **图表与公式择要**：选择最能解释机制或支撑结论的图和公式，不强制全量重现。关键数据表优先转为适合其含义的图表，读取 [实验图表准则](experiment-visualization.md)；定性映射或少量精确数字适合表格时仍可保留。
- **减少重复**：同一机制选最清楚的图和解释，不再由流程图、长列表及段落重复讲三遍；同一结果不同时放完整表格、重绘图和逐项数值复述。非核心细节用原文章节/表号定位，不默认另附全量数据或长复现清单。

### 结合批注与提问定位理解卡点

生成精读笔记或解释论文方法时，结合用户在目标论文上的批注与相关提问，针对具体卡点补充说明：

- **完整读取目标论文的批注与关联问题**：按 [本地读取](library.md#可信读取与提问上下文) 使用查询脚本与 `read_zotero_context.py`；保留页码、分支及缺失上下文状态，不依赖历史临时脚本。
- **围绕卡点解释**：区分术语或前置知识不清、监督对象混淆、流程不清、设计原因不明等情况。方法解释优先讲清“要解决什么问题 → 该设计施加什么约束 → 去掉它可能出现什么失败 → 原文或消融提供什么证据”，必要时用小例子连接已读 WFM 内容，再解释公式；只补当前理解需要的基础知识。
- **核对解释来源**：批注和提问用于识别学习需求，插件回答只作为待核对的理解线索。结论须回到论文正文、公式、图表或实验核验；发现插件解释与原文不一致时明确纠正，区分 `[论文…]`、`[推断]` 与尚未解决的阅读疑问，不把插件回答当作论文结论。
- **融入现有输出**：补充解释放入相关方法小节或讨论，保持问题与机制的主线，避免扩成旁支知识教程；“附录：个人思考”继续留空。记录未能读取批注或关联对话的具体情况，不声称已结合不可访问的记录，也不因缺少这些辅助记录而停止基于全文的精读。

### 论文类型判断

`read_mineru.py --toc` 会自动判定并给出依据（标题 > 摘要 > 章节结构 > 来源），
可直接采用；有疑问时按下表复核：

**技术型**（method/system/algorithm）满足任一：
1. **标题信号**：含具体方法名/系统名/算法名（如 "SmoothQuant"、"DQN"、"MAE"、"Transformer"），或 "Efficient"、"Low Overhead"、"Accurate"、"Novel" 等性能/创新描述词
2. **摘要信号**：描述"提出/设计/开发了某种方法或系统"（presents/proposes/develops/introduces a method），且含实验或仿真结果
3. **来源信号**：`itemTypeID` 为 `conferencePaper`(11) 偏技术型
4. **章节结构信号**：含 "Methods"、"Architecture"、"Experimental Results"、"System Model"

**综述型**（survey/review/tutorial）满足任一：
1. **标题信号**：含 "Survey"、"Review"、"Tutorial"、"State-of-the-Art"、"Comprehensive"、"Taxonomy"、"Advances in"
2. **摘要信号**：描述"综述/回顾/总结了某领域"（reviews/surveys/summarizes），通常不报告新实验数据
3. **来源信号**：`journalArticle`(22) 且发表在综述倾向期刊（IEEE COMST、IEEE Access）或标题含 "survey/review"
4. **章节结构信号**：含 "Classification"、"Taxonomy"、"Comparison of"、"Open Challenges"、"Future Directions"

其余（opinion、perspective、short communication）默认按技术型处理，但精简方法/实验部分。
信号矛盾时以标题和摘要为准；不确定时默认技术型。

### 流程

1. `query_zotero.py --key <KEY> --annotations` 取元数据与高亮，并用 `read_zotero_context.py --key KEY` 读取该论文已保存的关联提问
2. `read_mineru.py --key <KEY> --toc` 取目录与图表清单，确认论文类型
3. `read_mineru.py --key <KEY> --read` 读正文并判断内容主次（长文分段；必要时用 `--page N` 核对），选择核心机制、关键证据与卡点
4. `--copy-figures` 先取原图到临时目录，仅保留选用图；关键表格数据按实验图表准则转绘，核对数值、标注与实际渲染
5. 加载对应模版，按重点组织，允许合并章节，不逐字段扩写：
   - 技术型 → `template_technical.md`
   - 综述型 → `template_survey.md`
6. 附录「个人思考」留空，供用户手动补充（保留 `<!-- 后续手动补充 -->`，
   **其余模版注释一律删净**）
7. 先做内容检查：关键设计的解释链条是否完整，批注与反复提问的卡点能否凭笔记理解，删减是否切断必要背景、实现步骤或证据；发现缺口先补回，再删除重复内容。随后**跑质量门**：`lint_note.py --note <刚生成的笔记>`，**FAIL 清零再交付**。lint 检查格式与引用，不证明解释充分或内容无遗漏。

### 输出位置

1. **优先用户指定路径**
2. **默认**：当前项目根目录，文件与该项目已有笔记同级；图片进该项目根的 `figures/`
3. 无法判断项目归属时，询问用户

**文件命名**：`{论文简称}.md`（技术型）或 `{论文简称}_综述.md`（综述型），
优先遵循用户当前项目的既有笔记约定；没有既有约定时使用本 skill 的模板。

### 笔记内嵌图格式

与项目既有笔记一致（`<img>` 可控制缩放，markdown 的 `![]()` 不行）：

```html
<img src="figures/<sha256>.jpg" alt="图1: 图注摘要" style="zoom:80%;" />
```

文件名一律由 `--copy-figures` / `--img-tags` 给出，**不要手写哈希**。

### 精读原则

**三条基础要求**（格式与引用由 lint 检查，公式用途与解读质量另做内容核对）：

1. **每图必解读** —— 每张选入笔记的图后先一行加粗图注，再一段解读（这张图在讲什么 → 从中
   能读出什么 → 对应正文哪句）。**图注不等于解读**，把图注换个说法不算数。
   实测最容易犯的是"图后直接接下一个标题"。
2. **公式必重现** —— 正文只要出现「式 N」，本笔记内就必须有对应的
   `$$…\tag{N}$$` 块（**单行**，编号用论文原编号）并附「式 N 直觉」。
   引用一个读者在本笔记里看不到的公式，是精读笔记最典型的严谨性缺口。

   **公式直觉须说明操作与用途**：对每个选入笔记的公式，在直觉部分串起“做什么 → 为什么在此使用 → 在方法中起什么作用 → 服务什么目标”。解释关键输入输出、必要符号与运算含义，并连接前后步骤；损失公式说明监督对象及希望促成的行为，变换公式说明表示或计算方式的改变及其用途。根据理解需要展开，不只翻译符号或描述算式。区分预期收益与实测效果；如低位宽存储可降低表示成本，定点运算的推理加速还取决于实现与硬件，实际收益须有论文证据。
3. **论断必锚定** —— 结论性论断标出处：`[论文 §IV-B]`、`[论文 Table II]`、
   `[推断]`（自己的推论）、`[论文未涉及]`（论文没做的）。
   密度控制在结论句上，不求逐句。汇报时被追问"这是作者说的还是你读出来的"，
   全靠这个。

**其余约定**：

- 保留关键术语英文原文，首次出现时加括号中文注释
- 核心实验数值优先用合适图表呈现，原表可用 `--table N` 提取；按 `experiment-visualization.md` 判断图型、比较口径和必要表格
- 「与本人研究的关联」结合用户实际研究方向、任务与约束具体阐述；WFM 是示例方向，不是所有用户的默认课题
- **全文禁人称词**（"你/我/咱"）；指代研究者用「本人」。附录「个人思考」豁免
- 精读深度来自关键机制的因果解释与证据，不来自篇幅或全量覆盖；章节可合并，仍须覆盖问题、方法、关键实验和研究关联

配图按 [图表模块](figures.md)，精读交付检查按 [笔记质量门](note-quality.md)。这些笔记格式规则不套用到资源推荐、研究复盘、证据矩阵或导师讨论。
